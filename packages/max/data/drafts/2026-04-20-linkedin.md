I built PromptFuel because I watched a $100/month LLM budget become $500/month overnight—and nobody could tell me why.

The frustrating part? The problem was obvious in hindsight. We were throwing entire chat histories into context windows when we only needed the last two messages. Our error handling was re-prompting the same 2K-token context six times before failing gracefully. And nobody was actually measuring it.

That's when I realized: developers aren't avoiding optimization because they're lazy. We're avoiding it because there's no simple way to *see* what's happening. You can optimize what you can't measure.

So we built PromptFuel as a toolkit—free, open source—to give developers actual visibility into their prompt engineering. The CLI shows you token breakdown by section. The Chrome extension lets you test prompt changes in real-time and see the cost delta before shipping. The MCP server integrates directly into Claude Code.

We're not hitting venture scale metrics (75 weekly npm downloads, 0 GitHub stars 😅), but we're solving a real problem for people who care about their infra costs.

The lesson: most "optimization" problems aren't technical—they're visibility problems. Once you can see the waste, fixing it becomes obvious.
